# 一桌麻将 · 在线版 2.2.2

React + TypeScript + Vite前端，Node.js 24后端。支持1–4位真人在线，空座由可选难度的电脑补齐；保留浏览器本地单人模式。无需账号、付费API或大模型密钥。

## 启动

```bash
npm ci
npm test
npm run build
npm start
```

打开 http://localhost:3000。局域网内其他设备可访问这台电脑的IP和3000端口（需允许防火墙入站）。互联网游玩需部署后端。

开发时分别运行`npm run dev:server`和`npm run dev`，Vite的/api代理指向3000端口。

## 联机流程

1. 点击“联机房间”，填写昵称，创建房间并选择规则。
2. 房主复制邀请链接，其他玩家打开链接后填写昵称、加入房间。也可输入8位房间号。
3. 房主点击“开始牌局”；1–4位真人均可开局，空位由电脑补齐。
4. 四家分别提交同花色换三张、定缺选择。出牌、吃碰杠胡由服务端验证和结算。
5. 断线30秒或操作超时进入电脑托管；原浏览器刷新后重连，点“收回操作”接管。换牌／定缺60秒，行牌45秒。
6. 结束后可复盘四家完整手牌；房主继续下一局，累计座位分数。

房间只在开局前或本局结束后接受新玩家；房主离开后转交仍在房间的玩家。牌局中的离开座位由电脑接手。邀请链接只包含房间号，不含座位凭据；清除浏览器存储会失去原座位的重连凭据。

## 2.2.2修复国标存档刷新崩溃

旧版恢复国标行牌存档时，首轮渲染先执行胡牌判断，随后才进入加载页面；此时WebAssembly计分模块尚未就绪，触发`Cannot read properties of undefined (reading 'ccall')`。

- 启动加载器放在整个牌桌外层，计分模块完成初始化后才挂载牌桌、恢复计算和联机连接。
- 初始化失败显示可重试页面，保留原有存档；失败的初始化Promise不再永久缓存。
- 引擎调用增加就绪检查，尚未就绪时给出明确错误，不再读取undefined上的ccall。
- 新增真实前端入口的DOM回归：延迟实际WASM初始化，分别在助手开启和关闭时恢复国标存档；旧2.2.1入口均复现错误，新版均恢复14张手牌。

已有2.2.1仓库见[2.2.2升级说明](docs/UPGRADE_2.2.2.md)。数据库、房间协议和浏览器存档格式不变，无需清空存档。jsdom与esbuild仅用于开发测试，不增加线上服务依赖。

## 2.2.1显示修复与女声音色

- 中央只保留一个固定提示节点，最新牌也复用节点，连续出牌不再通过改变key反复重建。提示区固定88像素高并裁剪溢出，动作切换取消上一段动画，减少旧动画残留与纵向堆叠。
- 页面及提示区标记为不翻译，避免浏览器翻译重写牌局的动态文字节点。
- 自动选择优先考虑可用的中文女声及增强／自然音色，本地普通声音不再有最高优先级。默认语速从1.18调整为0.92，使用原生音高，不通过强行升调模拟女声。
- 新增音色下拉框、舒缓／柔和／轻快三档语速、当前音色显示和试听；选择自动保存。声音列表更新后可发现新音色，保存的声音消失时自动回退。
- 音色由浏览器和设备提供。网页不能凭空生成或安装高质量女声，不能保证每台iPhone都暴露同一款自然女声；本版未内置固定女声录音，也未添加付费语音API。

已部署2.2请按[2.2.1升级步骤](docs/UPGRADE_2.2.1.md)更新。与2.2后端接口兼容，前后端分开部署时只更新前端即可；单服务部署更新整个仓库。

## 本次界面、动画和语音更新

- 手牌在大桌面提升至64×90像素，弃牌32×45像素，中央最新牌64×90像素；放大余牌数、累计分、本局分和当前操作提示。
- 四家继续占用独立网格区域，不覆盖弃牌区；窄屏保留大牌面并支持横向滚动，助手移到牌桌下方。
- 出牌落位、摸牌入手、吃碰杠胡有动画反馈；系统开启“减少动态效果”时自动关闭动画。
- 新增独立“语音”开关与“试听语音”。真人和电脑确认出牌后播报牌名，实际成立的吃碰杠胡播报动作。
- 播报仅使用公开事件，不播报摸牌牌面或暗杠牌面；刷新、反复轮询、回放不重复朗读历史。快速模式队列优先保留动作与胡牌，淘汰过时的弃牌播报。
- 语音使用浏览器及系统的中文声音，优先可用的自然／增强中文女声；首次点击操作或试听后启用，不使用付费语音服务。实际发音与可用声音取决于设备。

已有2.1仓库可按[2.2升级步骤](docs/UPGRADE_2.2.md)更新；联机的前后端须一起更新，旧存档和SQLite不需要迁移。

## 已有算法与操作更新

- 电脑可选基础、标准、进阶；房主可在牌局中调整，之后的电脑／托管决策生效。
- 助手可实时切换偏进攻、攻守平衡、偏防守；联网助手由后端按当前玩家的公开信息视图计算，风格只影响自己的建议。
- 统计所有公开弃牌、副露、已胡和牌；历史弃牌单独记录，避免被吃碰的牌重复计数。结合副露、弃牌顺序、定缺和剩余牌估计对手风险。
- 默认优先减少向听和保留活张；进阶档增加有限的后续进张搜索。死听不再仅因结构0向听而占优。
- 抢牌按钮保持原位直到请求确认，显示提交状态与实际选择；旧轮询不会覆盖新操作，失败提示保留。合法动作采用语义匹配，JSON字段顺序不影响吃碰杠胡。

更新已有仓库见[2.1升级步骤](docs/UPGRADE_2.1.md)，算法边界见[AI与助手说明](docs/AI_AND_ASSISTANT.md)。

## 规则与界面

- 川麻：108张、不吃，同花色换三张、定缺、血战到底、一炮多响及独立杠分／流局查叫退税；已胡玩家在结束前仅亮一张和牌，其余手牌保持隐藏。
- 国标：136张、无花牌、吃上家、完整番型计分；8分起胡限制默认开启，开局可关闭，仍保留实际番数和8分底分。
- 两种模式均可关闭番数，按固定底分结算；保留已有番型开关。
- 现代平面牌桌，桌面优先、手机横屏可用；提示、有效进张、建议、音效、本地续局及结束后牌谱回放。
- 服务端管理牌墙和手牌。每位玩家只收到自己的手牌及公开信息；座位凭据仅在浏览器和请求头使用，服务端仅保存凭据哈希。

## 部署

**最省事：Render一个Node Web Service同时运行前后端。** 仓库已有`render.yaml`，默认选择free计算实例。

Vercel或GitHub Pages也可部署前端，但联网房间需要独立Node后端；设置`VITE_ONLINE_API_URL`并在后端配置`ALLOWED_ORIGINS`。GitHub Actions负责测试、构建和可选Pages发布。

完整步骤与免费套餐限制见[部署说明](docs/DEPLOYMENT.md)。API协议见[API文档](docs/API.md)，规则见[引擎说明](docs/RULES_AND_ENGINE.md)，验证范围见[验证记录](docs/VALIDATION.md)。

## 数据与范围

后端使用Node内置SQLite，默认`.data/rooms.sqlite`。持续访问延长房间有效期，无人访问2小时后房间过期。SQLite文件在本地或持久磁盘上可跨进程重启保留；Render免费实例的磁盘是临时的，重启、重新部署或休眠可能丢失房间。原托管版曾使用D1保存房间；本次原Site接口返回项目不存在，2.2更新交付为Node完整源码，需推送自己的仓库并重新部署。

这是一套邀请房间型麻将项目，没有账号体系、公开匹配、聊天或排位。单人本地模式不依赖联机服务。
